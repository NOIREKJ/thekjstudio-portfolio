# the KJ Studio — 악기가 되는 포트폴리오 사이트

**작성일:** 2026-07-21
**상태:** 설계 확정, 구현 계획 대기
**대상:** thekjstudio-portfolio 저장소 `v2` 브랜치 (백지에서 재구축)

---

## 1. 무엇을 만드는가

방문자가 **누르면 소리가 나고 작업이 열리는** 진입 화면을 가진 개인 사이트.
읽는 문서가 아니라 **만지는 악기**로 동작한다.

만드는 사람은 작곡가이자 앱 개발자다. 이 사이트의 존재 이유는 그 두 직업이 겹치는
자리에서만 나올 수 있는 물건을 만드는 것이다. 그림으로는 일러스트레이터를 못 이기지만,
**소리 나는 인터랙션**은 이 조합에서만 나온다.

### 판단 기준선

설계상 결정이 갈릴 때는 이 질문으로 판단한다:

> **이것이 음악과 앱, 두 세계를 잇는가?**

잇지 않으면 아무리 멋져도 뺀다.

## 2. 왜 이렇게 정해졌는가 (결정 기록)

브레인스토밍에서 나온 결정과 그 근거. 나중에 "왜 이랬지"가 나올 때 여기를 본다.

| 결정 | 근거 |
|---|---|
| 청중은 "작곡가이자 개발자"라는 정체성 하나 | 음악 팬용/클라이언트용을 나누면 두 개의 반쪽 사이트가 된다. 조합 자체가 개성 |
| 손그림·콜라주 아트워크는 안 한다 | 참조한 Jacob Collier 사이트의 아트워크는 전담 아티스트 작업물. 따라가면 남의 옷이 됨. 본인이 명시적으로 제외한 유일한 항목 |
| 개성 = 장난감 + 낯선 탐색 + 소리 | 시각 장식이 아니라 **행동과 소리**로 개성을 만든다 |
| 세 컨셉(콘솔·건반·악보)은 경쟁이 아니라 한 물건의 세 얼굴 | 트리거 / 레이어 / 시간축 = DAW. Phase로 순서만 매긴다 |
| Phase 1은 건반(트리거) | 본인이 개성의 정체로 **가장 먼저 고른 것**이 "만지면 반응하는 장난감". 그리고 콘솔·악보는 건반 없이는 검증조차 안 된다 (섞을 것도, 늘어놓을 것도 없으므로) |
| Next.js·Once UI를 버리고 백지 | 진입 화면이 전부 클라이언트(Web Audio·인터랙션)라 SSR의 이득이 거의 없고, 서버/클라이언트 경계가 오디오 코드에서 계속 걸린다. Once UI는 `.agents`에 *"불필요한 애니메이션 없이, 절제되고 그라운디드하게"*라고 명시된 시스템이라 악기 사이트와 정면 충돌 |
| 저장소는 유지, `v2` 브랜치에서 재구축 | 코드는 백지로 쓰되 저장소·히스토리·배포 주소가 살고, 완성될 때까지 기존 사이트가 계속 서비스된다 |
| 기존 콘텐츠도 옮기지 않고 다시 쓴다 | 본인 결정. 더불어 현 저장소는 CC BY-NC 4.0(상업적 사용 금지)에 Once UI 상표까지 포함하고 있어, **온전히 본인 저작물인 사이트**로 성립시키려면 어차피 필요한 정리였다 |

### 명시적으로 접은 것

- **"피아노"라는 형태** — 확정한 것은 *"누르면 소리 나고 열린다"는 문법*이지 피아노가 아니다.
  누르는 면은 타일·돌·창문·스위치·색면 무엇이든 될 수 있고, 형태는 구현 중에 정한다.
  "음악가 사이트에 피아노"는 가장 뻔한 선택지이므로 기본값으로 두지 않는다.
- **Phase 2(콘솔)·Phase 3(악보)** — 문서에만 남기고 지금은 만들지 않는다.

## 4. 구조

네 덩어리로 나눈다. 경계의 목적은 **오디오 엔진이 화면을 모르고, 화면이 오디오 내부를
모르게** 하는 것이다. 그래야 Phase 2에서 화면만 갈아끼울 수 있다.

```
① 작업물 데이터  (works/*.md — 빌드 타임)
        │
        ▼
┌───────────────┐   play(id)   ┌───────────────┐
│  ② 건반 화면   │ ───────────▶ │ ③ 오디오 엔진  │
│  배치·모양·반응 │              │  순수 로직     │
└───────────────┘              └───────────────┘
        │
        ▼
④ 작업물 상세 페이지 (조용한 문서)
```

### ① 작업물 데이터

`src/works/*.md` — 파일 하나가 작업물 하나. frontmatter로 건반이 자동 생성된다.

```yaml
---
slug: consolation
title: "위로 (Consolation)"
kind: music          # music | app — 건반의 배치와 색을 가른다
note: "E3"           # 이 작업의 음. 5개가 모여 하나의 화음이 된다
sound: /audio/keys/consolation.mp3   # 없으면 note로 합성음 폴백
year: 2024
---
```

**작업물 추가 = md 파일 하나 추가.** 코드는 건드리지 않는다.
`import.meta.glob`으로 eager 로딩하고 frontmatter를 파싱한다.
(gray-matter는 브라우저에서 Buffer 폴리필이 필요하므로 쓰지 않는다.)

`note` 5개는 아무렇게나 눌러도 불협이 되지 않도록 **하나의 스케일 안에서** 고른다.
방문자가 마구 눌러도 음악이 되는 것 — 그것이 이 사이트의 Randomizer다.

### ② 건반 화면

누르는 면의 배치·모양·반응만 담당한다. **소리를 직접 다루지 않고** `play(id)`만 호출한다.
`kind`에 따라 음악/앱이 시각적으로 구분되지만 **섞여서** 배치된다 — 분리하면 기준선에 어긋난다.

### ③ 오디오 엔진

화면을 전혀 모르는 순수 모듈. 외부에 노출하는 것은 다음뿐이다:

- `unlock()` — 첫 사용자 제스처에서 AudioContext 활성화
- `preload(works)` — 샘플 디코드, 실패 시 합성음으로 폴백
- `play(id)` / `release(id)` — 동시발음(폴리포니), 페이드 처리
- `setMuted(bool)`

Web Audio API를 직접 쓴다. Tone.js는 쓰지 않는다 — 필요한 것이 잠금 해제·디코드·폴리포니·페이드
정도라 라이브러리를 얹으면 경계만 흐려진다.

### ④ 작업물 상세 페이지

**여기서는 실험하지 않는다.** 읽기 편한 평범한 문서다.
진입 화면이 시끄러운 만큼 안쪽은 조용해야 한다. 마크다운 본문을 렌더링하고, 이미지와 텍스트만 있다.

## 5. 처음부터 반영할 제약

이건 나중에 붙이는 게 아니라 처음부터 설계에 들어간다.

- **소리 없이도 완전히 작동해야 한다.** 음소거 상태, 사무실, 스크린리더 사용자에게도
  온전한 사이트여야 한다. 소리는 **덤이지 관문이 아니다.**
- **자동재생 금지 대응.** 브라우저는 첫 사용자 제스처 전에 소리를 낼 수 없다.
  따라서 (a) 진입 화면은 무음 상태에서도 "눌러보고 싶게" 생겨야 하고,
  (b) 무음 상태에서도 시각 반응은 완전히 살아있어야 한다.
- **키보드 조작.** Tab·화살표로 건반 이동, Enter/Space로 열기. `A S D F` 연주는 그 위에 얹는다.
- **모바일 멀티터치.** 두 손가락으로 화음이 되어야 한다.
- **`prefers-reduced-motion` 존중.** 모션을 줄이되 기능은 유지한다.
- **음소거 토글은 항상 보이는 곳에.** 소리 나는 사이트의 최소 예의다.

| 테스트 | Vitest | 아래 참조 |

### 옮겨오는 것 / 버리는 것

**옮긴다:** 본인이 촬영·제작한 이미지만 — 프로필 사진, 갤러리 사진 8장(Phase 2용 보관),
작업물 실제 스크린샷(`horizontal-1-noire.png`, `horizontal-kj-01/02.png`, 한일페이 앱 화면 등).

**버린다:** Next.js App Router, Once UI 전체, `RouteGuard`와 비밀번호 API, Mailchimp,
기존 `src/resources/` 설정 구조, 그리고 아래의 템플릿 유래물 전량.

**콘텐츠는 옮기지 않고 다시 쓴다.** 기존 작업물 글 5편은 새 사이트의 톤에 맞춰 새로 작성한다.
건반을 눌러 들어온 사람이 읽는 글은, 스크롤해서 읽는 글과 길이도 호흡도 달라야 한다.

### 저작권 — 템플릿 유래물 전량 제거

현재 저장소는 **CC BY-NC 4.0**이다. 출처 표기 의무가 있고 **상업적 사용이 금지**된다.
본인 포트폴리오에 걸려 있어서는 안 되는 제약이므로, `v2`는 템플릿에서 유래한 것을
코드·에셋·문서 전부 제거하고 **본인 저작물로 새로 성립시킨다.**

제거 대상:

| 대상 | 비고 |
|---|---|
| `LICENSE` (CC BY-NC 4.0) | 본인 명의 라이선스로 교체 |
| `public/trademarks/wordmark-*.svg` | **Once UI 워드마크(상표).** 상표는 CC 라이선스로 커버되지 않는다 |
| `public/images/og/home.jpg` | Magic Portfolio 홍보 이미지 |
| `src/app/blog/posts/*.mdx` 11편 | Once UI 문서 |
| `project-01/` 더미 이미지 | `cover-01~04`, `avatar-01`, `image-03` |
| `.agents` | Once UI 개발 규칙 문서 |
| `README.md` | 템플릿 소개문 |

**완료 판정:** `v2` 브랜치에 Once UI·Magic Portfolio에서 온 파일이 한 개도 남아 있지 않을 것.
확인은 파일 단위 대조로 한다. 애매한 것은 남기지 말고 지운다.

## 7. 소리 조달

**합성음으로 먼저 짓고 나중에 교체한다.**

Phase 1 개발은 `note` 값으로 생성한 합성음으로 시작한다. 나중에 md의 `sound` 필드를
채우면 그 건반만 자동으로 실제 오디오로 바뀐다.

- 개발이 녹음을 기다리지 않는다
- 한 개씩 교체해도 된다 — 5개를 한꺼번에 준비할 필요가 없다
- 음악 2개(위로·가로등)는 기존 곡에서 4~8초 발췌가 가능하고, 앱 3개는 새로 만들어야 한다

**주의:** 실제 오디오로 교체할 때 5개의 음량·질감·길이를 맞추는 작업이 별도로 필요하다.
발췌본과 합성음이 섞이면 톤이 갈린다.

## 8. 검색 노출 (Phase 1.5)

Next.js를 버리면서 잃는 유일한 실질적 자산이다. 공짜로 따라오지 않으므로 별도 항목으로 둔다.

포트폴리오는 이름으로 검색해 찾아오는 경로가 실제로 존재한다. Phase 1이 동작한 직후,
정적 프리렌더 + 라우트별 메타 태그 + OG 이미지 + sitemap을 처리한다.
기존 사이트의 `baseURL`이 아직 템플릿 기본값(`demo.magic-portfolio.com`)이었으므로
어차피 지금도 제대로 동작하지 않았다 — 이번에 올바른 도메인으로 정리한다.

## 9. 테스트

현재 저장소에는 테스트가 전혀 없다. 이번에 최소한을 들인다.

- **오디오 엔진** — 화면을 모르는 순수 모듈이므로 유닛 테스트가 가능하고, 가치가 가장 높다.
  잠금 해제 상태 전이, 폴리포니 관리, 샘플 없을 때 합성음 폴백, 음소거.
  AudioContext는 목으로 대체한다.
- **작업물 데이터 로딩** — frontmatter 파싱, 필수 필드 누락 시 동작.
- **건반 화면** — 키보드 조작과 접근성 위주의 스모크 테스트.
- 소리가 실제로 어떻게 들리는지는 테스트할 수 없다. 그건 사람이 듣고 판단한다.
